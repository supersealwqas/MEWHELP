# CH04 评估题集

题集位于 `data/evaluation/ch04.json`，共72题：24题校准、48题固定验收。依据 `data/kb/manifest.json` 登记的六份原文标注，未修改原文。每道题都是能独立理解的单轮问题。

校准集用于选择阈值及验证提示词；固定验收集不用于调参。运行程序应保存题集、原文、切分器、模型和提示词版本，避免资料变化后继续使用旧结果。

## 事实划分

校准主题包括：换货条件、换货运费及申请步骤，非质量问题不支持退货的商品，预售和定金，W20/W40/W60饮水机，订单取消、支付、补货、猫窝清洗、积分入账，以及售后表中的维修/换货/其他行。

固定验收主题包括：退货与价保的起算时间，退款处理时限与到账承诺，运输破损与人工入口，会员等级及生日权益，积分抵扣与有效期，运费、开票、优惠券、配送范围，猫砂盆型号、喂食器与独立摄像头、加热垫、猫爬架、设备故障和保修。

同一事实的口语版本、比较题及筛选版本留在同一个集合。多证据题连接的相近主题在同一集合内合组，例如固定集的会员、积分抵运费和偏远运费归为 `eval-membership-points-shipping`。无答案题按所缺信息独立分组。

事实隔离不等于整份文件或整块语料隔离。例如售后处理表同时有维修、换货和退款行：前两类题在校准集，退款处理与到账区分在固定集；它们可以落在同一个表格块，但询问的独立事实不同。积分入账和积分花费属于不同章节、不同事实。无答案题问某型号未公布的功率，也不等于把该型号已公布的容量事实移入固定集。

## 字段与证据约定

JSON根节点是数组，每项必须包含 `id`、`split`、`fact_group`、`bucket`、`difficulty`、`query`、`filters`、`answerable`、`evidence_groups`、`required_facts`、`reference_answer`、`forbidden_claims`。`filters` 可省略为空映射；其余字段必填。额外字段和隐式类型转换均拒绝。

每条定位器由 `source_key`、`section_path`、`quote` 组成。来源为清单生成的 `doc:文件名.md`，章节为字符切分器保留的完整路径，片段必须逐字存在于该知识块正文中。片段只负责稳定定位；关键事实需由定位到的完整知识块支持，不能把片段改写成答案，也不能把其他型号的正文当证据。

```json
"evidence_groups": [
  [
    {"source_key": "doc:甲.md", "section_path": "手册 / 保修", "quote": "保修十二个月"},
    {"source_key": "doc:乙.md", "section_path": "常见问题 / 保修", "quote": "保修一年"}
  ],
  [
    {"source_key": "doc:甲.md", "section_path": "手册 / 寄修", "quote": "联系客服登记"}
  ]
]
```

上例仅解释格式：第一组两条证据任选其一，第二组仍必须覆盖。每条定位器本身都必须唯一匹配，不能让有效分支掩盖另一条失效分支。不存在的来源、错误章节、原文片段变更、匹配多个块、非活动块或被筛选条件排除，都会使验证失败。数据库自增主键不写进标注文件，运行时才解析为当前快照的主键集合。

无答案题固定使用 `answerable=false`、`evidence_groups=[]`、`required_facts=[]`，参考答案说明无法确认的具体信息。不能给不存在的型号套用邻近型号参数，也不能用处理时限编造到账承诺或实时订单状态。无答案题不进入检索召回率分母。

## 筛选条件

只允许现有字段：`source_key`、`content_type`、`category`、`is_key_clause`。前三项接受非空字符串或非空字符串列表；最后一项接受布尔值或非空布尔列表。列表表示任选其一，字段之间同时满足。

`category` 是真实知识块的父章节路径，如“商品规格手册”或“售后手册”，并不是商品品类。没有虚构 `product_category`。重点条款来自原文清单的 `key_sections`，不按题目需要临时增加标签。

## 加载和复核

`load_dataset(path, *, chunks=None) -> list[EvalCase]` 先检查字段、72题总量、每桶4/8题、题号唯一性和事实组不跨集合，再核验所有证据。默认从仓库六份原文执行生产字符切分器：400字符基础块、60字符完整句重叠、表格10行。当前得到52块：FAQ 15、退货政策9、开票配送3、会员权益3、售后手册8、商品规格14。

离线校验以 `len` 做保守硬限检查，分块仍使用真实生产字符规则；真实评估运行还需以所用编码模型核验硬限。调用方传入 `chunks` 时，按该冻结语料核验。`resolve_evidence(case, chunks) -> list[set[int]]` 提供评估实际使用的证据主键集合。

```bash
uv run python -m app.evaluation.cli validate
uv run pytest tests/rag/test_eval_dataset.py
```

验证器测试使用独立手工语料覆盖组内可替代、组间必需、错误计数、事实组泄漏、缺失或歧义证据、错误答案标记及错误筛选字段；另用发布题集与真实字符切分器执行整体验证。

## 已知限制

- 题集根据本地原文逐题核对，独立子 Agent 另检查了全部15道多证据题；尚未经过人工全量标注复核，不能据此声称线上准确率已经达标。
- 自动检查能发现相同 `fact_group` 跨集合，不能自动理解不同组名下的语义重复。以后补题或修改问题时，仍需检查事实本身是否泄漏。
- 资料原文把金卡商品折扣写为“95折”。相关题保留原文，并禁止自行改成“9.5折”或与银卡折扣互换；该业务原文有疑点，需业务方确认后才能更新题集和原文版本。
- 文本存在并不自动证明参考答案的每个事实都正确；自动定位检查不能代替事实审阅。没有答案的判断基于本次六份静态资料，不代表商家在其他系统也无法回答。
- 难题覆盖条件、比较和多个证据，不验收多轮指代能力。门槛是否有效、四策略效果和模型忠实度必须以独立真实运行报告为准。

## 扩展题集 ch04-extended.json

在原有 72 题之外另有一份 320 题扩展集，与主集并存，不替换主集。来源为参考项目 `tests/data/eval_ch04.jsonl` 的 300 题（240 道可回答 + 60 道无答案），逐题迁移为本项目的 `source_key / section_path / quote` 精确定位格式，另补充 20 道 `D_filter` 筛选题。

| 桶 | 题数 | 说明 |
| --- | ---: | --- |
| A_policy | 60 | 政策规则及适用条件 |
| B_model | 60 | 具体型号及相近型号混淆 |
| C_colloquial | 60 | 口语、情绪和同义问法 |
| D_filter | 20 | 明确限定真实元数据（参考项目无此桶，由单来源题加筛选条件生成）|
| E_multi | 60 | 同轮综合多个必需证据 |
| F_unanswerable | 60 | 库外、实时信息或证据不足 |
| 合计 | 320 | 104 校准 / 216 固定 |

### 迁移与标注方式

- 章节定位与 `quote` 由脚本按 `resolve_evidence` 的真实约束（quote 必须是对应 chunk `answer` 字段的子串，且在相同 source_key 与 section_path 下唯一匹配）自动生成，260 道可回答题的 384 条定位器全部唯一命中。
- `difficulty`、`fact_group`、`reference_answer`、`forbidden_claims` 由 `gemini-3.8-flash-high` 分批补齐，提示要求只依据给定证据作答、不添加证据外信息。
- 参考项目原文写「10 元运费」，本项目知识库为「6 元运费」，迁移时统一为本项目口径。

### 与主集的质量差异（必须如实记录）

- 主集 72 题的 `reference_answer` 与 `forbidden_claims` 经人工逐条核对；扩展集的这两个字段由模型生成，**未经人工复核**。
- `difficulty` 分布偏易：easy 193 / medium 112 / hard 15。hard 集中在 12 道 E_multi 多证据题，与主集 easy 22 / medium 32 / hard 18 的分布不同，两集难度不可直接比较。
- 事实组按组名哈希分配 split 后校正，保证无跨集合泄漏（校验器已确认 0 泄漏），但 `D_filter` 校准题只有 1 道，该桶的阈值校准样本不足。
- 扩展集尚未用于正式校准与四策略比较；在跑出真实数字前，不得引用其任何成绩。

### 题量不再写死

校准与比较的题数一律取自数据集本身，不再硬编码 24/48/72：

- `validate` 与真实运行都用 `load_dataset(..., expected_size=None)`，只要求每桶在两种 split 都有题。
- `policy.json` 的 `calibration_case_count` 记录当次实际校准题数。
- `validate_policy` 在 `compare` 时用当前数据集的校准题数核对 policy，题数不一致直接报错，避免把主集 24 题的校准套到扩展集上。

主集仍保持 24 校准 / 48 固定，摘要 `f91e0e43…` 不变；扩展集为 104 校准 / 216 固定，摘要 `85561aaa…`。
