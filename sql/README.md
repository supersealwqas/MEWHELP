# SQL 脚本说明

当前应用实现到第二章。表结构以 `app/models/customer_service.py` 为准；FAQ 的问题、答案、分类和顺序以 `ch02-seed.sql` 为准，代码中的 `app/db/seed.py` 已同步这 6 条问答。

## 当前应用初始化

推荐在项目根目录执行：

```bash
uv run python -m app.db.init_db
```

该命令创建缺失的四张表，并补充 FAQ、演示会话、工具调用消息和人工工单。FAQ 按固定 ID 补缺失项，不覆盖已有记录。

如果需要手动检查或在空库中建表，先选择目标数据库，再按顺序执行：

1. `ch02-ddl.sql`：建立 `conversations`、`messages`、`faq`、`tickets`，包含会话标识、轮次字段、工具结果唯一约束和状态校验。
2. `ch02-seed.sql`：写入 6 条 FAQ，不创建演示会话和工单。它会先删除这 6 个问题的同名记录再插入，其他 FAQ 保留；有其他记录时，全表行数可以超过 6。

两种初始化方式择一使用。SQL FAQ 脚本使用自增 ID，代码使用固定 ID；在已有数据的库中交替执行，不能保证 ID 对应同一个问题。FAQ 演示内容包括 7 天无理由退货、48 小时发货、满 99 元包邮、未满 10 元运费等，不代表真实商城政策。

## 已有数据库

`CREATE TABLE` 脚本用于新建表，不是旧表升级脚本。`app.db.init_db` 使用的 `create_all()` 同样不会为已有表补列或补约束。已有库如果缺少 `session_id`、`turn_id` 等字段，需要结合存量记录另做迁移，不能直接重复建表。

更新种子文件不会自动刷新数据库里的旧答案。需要重新进行模型评估时，先停止使用测试库的服务，再按项目根 README 的流程重建 `mewhelp_test`；不要为刷新 FAQ 清空应用库。

## 后续章节

以下脚本保留作后续章节使用，不需要为了运行当前应用而全部导入：

| 脚本 | 前置条件与用途 |
|---|---|
| `ch03-ddl.sql` | 建知识片段表与问答抽取暂存表。 |
| `ch03-seed.sql` | 依赖新版第二章表结构；补充两个固定会话及已完成的问答轮次，不清理已有会话。运费示例与第二章一致，为 10 元。 |
| `ch03-staging-review.sql` | 在第三章建表后执行，扩充人工审核状态；历史 `kept` 状态修正按脚本中的日期界限执行。 |
| `ch04-ddl.sql` | 依赖第二章会话表，建立低置信度问题池和编造个案台账。 |
| `ch06-ticket-type.sql` | 第六章再启用“退款”工单类型；当前代码只支持售后、投诉、咨询。 |
| `ch07-ddl.sql` | 依赖第二章会话表，增加摘要字段。 |
| `ch08-ddl.sql` | 建工具审计表，当前工具执行器尚未写入该表。 |
| `ch09-ddl.sql` | 依赖第四章问题池，建审核队列、评估记录并补充关联字段。 |
| `ch10-ddl.sql` | 依赖第四章问题池，建主题分类表。 |

后续 `CREATE TABLE` / `ALTER TABLE` 脚本按对应章节执行一次，不应作为可任意重跑的初始化命令。
